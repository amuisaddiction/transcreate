# Hackathon Submission Checklist

## Eligibility and repository
- [ ] Public repository URL is correct.
- [ ] MIT or another suitable open-source license is committed and visible.
- [ ] README describes the product, setup, workflows, and limitations.
- [ ] Fresh clone setup has been tested.
- [ ] No secrets in current files or Git history.
- [ ] Source and assets required to run the project are included.

## Live demo
- [ ] Public demo URL works without login.
- [ ] Demo stays free and unrestricted for judging.
- [ ] Actual Qloo request succeeds on the deployed server.
- [ ] LIVE status appears only after successful verification.
- [ ] SAMPLE mode is visibly labelled and never presented as live.
- [ ] Error, empty, timeout, and ambiguity states work.
- [ ] Demo checked in incognito and on mobile.

## Technical proof
- [ ] Agent uses actual Qloo-returned data.
- [ ] Candidate choices are validated against the real returned set.
- [ ] Rewrite verification and bounded retry are demonstrated if working.
- [ ] Receipts are sourced from observations, not model-generated claims.
- [ ] README includes a redacted request-to-result example.
- [ ] Known limitations are explicit.

## Presentation
- [ ] Explain the problem and target user.
- [ ] Explain why Qloo is essential to the workflow.
- [ ] Show one real example end to end.
- [ ] Show a keep-original or rejected-candidate case only if it genuinely happened.
- [ ] Avoid claims of causal effects or individual preferences.
- [ ] Confirm the current official submission form's video/text requirements and deadline.
